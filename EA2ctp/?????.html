1 概览

EA2ctp 把 MT4 里的策略决策转成交易指令，交给 SimpleCTPConsole 在 CTP 通道下单。本方案不使用任何网络协议中转，只用一个共享 CSV 文件做桥接，因此 MT4 和控台可以各自独立启动、独立重启。

角色路径职责
MT4 终端EA2ctp\terminal\运行 EA，产出决策，写指令文件
EA 源码EA2ctp\terminal\experts\Moving Average.mq4MA 交叉策略，输出信号
指令文件EA2ctp\terminal\experts\files\ctp_signals.csvEA 写 / 控台读，单行 CSV
CTP 控台strategy2gateway-ctp\Debug\SimpleCTPConsole.exe轮询指令文件，双通道下单
网关strategy2gateway-ctp\gateway\aqgw.pyHTTP 8222，aq 上游通道
关键设计：EA 只负责「何时买/卖」，不碰价格、不碰手数精度、不碰通道选择。所有交易细节（品种映射、参考价、20×spread 保护价、groupKey、CSV 落盘）由控台的 SignalWatcher + OrderRouter 统一处理。这样 EA 可以极简，后续换策略对控台零影响。
本项目为纯 CTP 模式，网关不参与、也不需要启动。控台配置 order_mode=ctp_only，EA 信号经 SignalWatcher 调用 g_orderRouter.Submit() 后只下发 CTP 一条腿，orders.csv 只会出现 CTP 行，网关订单数保持不变。若把 order_mode 改回 parallel，同一套桥接代码会自动恢复 CTP + 网关双通道（此时才需要先启动网关）。

信号从 EA 写盘到控台消费的延迟上限约 800ms（轮询周期），实测端到端约 1 秒。本项目 order_mode=ctp_only，网关不参与，无需启动。

4 首次配置

4.1 控台 config.ini

在 ctp_console\config.ini 里确认这两项（Debug\config.ini 会在构建时被根配置覆盖，所以改根目录那份）：

order_mode=ctp_only
ea_signal_file=..\..\terminal\experts\files\ctp_signals.csv

相对路径以 exe 所在目录（ctp_console\Debug）为基准，向上两级正好回到 EA2ctp，再进 terminal\experts\files。这样整个 EA2ctp 目录可以整体拷贝到任何机器、任何盘符，配置无需修改。

不配置时默认读 exe 目录下的 ctp_signals.csv。控台启动时会打印实际生效路径：

- EA2ctp signal watcher: ..\..\terminal\experts\files\ctp_signals.csv

4.2 品种映射

EA 传的是 MT4 图表品种名（如 ru），控台用 MatchInstrument() 到 instruments= 列表里做前缀匹配，得到 CTP 合约代码：

EA 输出instruments 配置匹配结果
ruru2701,...ru2701
agag2601,...ag2601
ru2701（完整代码）ru2701,...ru2701（精确命中）
前缀匹配要求 instruments 里确实存在该品种合约，否则控台打印 [EA2CTP] unknown symbol prefix 并丢弃该信号。

4.3 EA 参数

参数默认含义
Lots1手数
BidAskDif5传给控台的点差系数，控台用 price ± 20×BidAskDif 生成 CTP 保护价
MovingPeriod12MA 周期
MovingShift6MA 偏移

5 编译 EA（老版 MT4 注意点）

本项目终端是 MetaTrader 4 build 225，语法支持非常老，以下写法会直接编译失败：

会报错的写法本项目替代写法
FILE_OPEN_ALWAYS / FILE_SHARE_READ / FILE_SHARE_WRITEFILE_CSV|FILE_WRITE
FILE_WRITE_ADD（追加）不用；文件每次被控台清空，覆盖写即可
INVALID_HANDLEhandle < 0
DoubleToString(x, n)字符串拼接隐式转换："a" + lots
IntegerToString(x)同上，隐式转换
break 写在 if 里（不在循环内）保证 break 只在 for 体内

5.1 编译步骤

  1. 打开 terminal\MetaEditor.exe
  2. File → Open，选择 experts\Moving Average.mq4
  3. 按 F7 编译，Compile 窗口应显示 0 error(s), 0 warning(s)
  4. 生成的 Moving Average.ex4 会自动落在 experts\ 目录
  5. 回 MT4，右键图表 → Expert Advisors → Refresh，再重新挂载 EA
MT4 运行中无法覆盖 .ex4 时会报 cannot open file ... expert was not reloaded。此时先从图表移除 EA，再编译，再挂回。

6 启动顺序

纯 CTP 模式只需两步：先启动控台，再在 MT4 挂 EA。启动控台时要保证 CTP 行情已就绪，否则信号会带着 0 价格进场。

6.1 网关（本项目不需要启动）

order_mode=ctp_only 下 EA 信号只报 CTP，网关进程无需运行。仅在把模式改回 parallel 做双通道验证时，才需要先启动网关。

cd E:\aqntFuturesCn\approachExamples\strategy2gateway-ctp\gateway
python aqgw.py --symbols ru,ag --login  --password  `
  --srv-host 117.72.80.248 --srv-port 443 --port 8222

自检：http://127.0.0.1:8222/health 返回 connected=true。

6.2 启动控台

cd E:\aqntFuturesCn\approachExamples\strategy2gateway-ctp\Debug
.\SimpleCTPConsole.exe
必须在 Debug 目录启动，因为 config.ini 用相对路径加载；建议直接双击 exe，不要用后台隐藏窗口方式启动（PDCurses 会在会话结束时被一起杀掉）。

自检：4444、4445 端口处于 LISTENING，日志出现 CTP trade ready。

6.3 挂载 EA

  1. MT4 登录账户
  2. 打开目标图表（实证环境为 ru M1）
  3. 导航器里拖 Moving Average 到图表，勾选 Allow live trading
  4. 参数：Lots=1、BidAskDif=5、MovingPeriod=12、MovingShift=6
  5. 图表右上角出现笑脸，Experts 标签页出现 loaded successfully

6.4 可选：控台守护

PDCurses 控制台在后台/会话切换时可能异常退出。可在计划任务里挂一个 60 秒轮询的 watchdog，检测 4444 端口，缺失则重启 exe。本仓库提供脚本 strategy2gateway-ctp\strategy\_watchdog.ps1。

7 指令格式

文件里每行一条指令，7 列，无表头，无引号包裹：

action,symbolPrefix,type,offset,lots,bidAskDif,comment
BUY,ru,M,OPEN,1,5,ma_golden
SELL,ag,M,CLOSE,1,1,ma_death_close
列取值说明
1 actionBUY / SELL方向
2 symbolPrefixru / ag / auMT4 图表品种名，控台负责映射
3 typeM / L / D市价 / 限价 / 撤销
4 offsetOPEN / CLOSE开仓 / 平仓
5 lots整数手数
6 bidAskDif数值保护价系数，控台算 price ± 20×bidAskDif
7 comment任意文本原样写入 orders.csv 末列，便于溯源
保护价机制：控台拿到参考价后不会原样报出，而是 买入价 + 20×bidAskDif、卖出价 − 20×bidAskDif，再以 IOC 委托发出。这是一个有意为之的成交保障：宁可让价，也要立即成交、不留挂单。EA 端无需关心这个细节。

9 验证方法

每次跑完一批信号，按下面四步核对，能覆盖全链路：

9.1 EA 有没有产出

Get-Content "EA2ctp\terminal\experts\logs\20261103.log" -Tail 20 | Select-String "EA2CTP"

应看到 [EA2CTP] MA golden cross 与 [EA2CTP] SIGNAL: ... 成对出现。

9.2 中转文件有没有被及时消费

Get-Item "EA2ctp\terminal\experts\files\ctp_signals.csv" | Select-Object Length,LastWriteTime

空闲状态下 Length 应为 0（信号已被读取并清空）。长期非 0 说明控台没跑或 ea_signal_file 指错。

9.3 订单流水

Get-Content "strategy2gateway-ctp\Debug\orders.csv" | Select-String ",ea_ma,"

一笔信号应产生两行 NEW（GW + CTP），同一 groupKey；随后可能出现一行 FILL。

9.4 两通道持仓

# CTP 侧
Get-Content "strategy2gateway-ctp\Debug\feedserver.log" -Tail 30 | Select-String "positions refreshed"
# 网关侧
Invoke-RestMethod "http://127.0.0.1:8222/positions" | ConvertTo-Json
Invoke-RestMethod "http://127.0.0.1:8222/health"   | ConvertTo-Json

CTP 的 long/short 与网关的 positions 应反映同样的净方向；两套系统持仓独立计算，测试结束后需分别平掉。

10 故障排查

现象原因处理
cannot open file ...ex4, expert was not reloadedMT4 运行中占用旧 ex4图表移除 EA → 编译 → 重新挂载
FILE_SHARE_READ / FILE_OPEN_ALWAYS / INVALID_HANDLE not definedbuild 225 不支持这些常量改 FILE_CSV|FILE_WRITE，用 handle < 0 判错
DoubleToString / IntegerToString is not defined老版无此函数用字符串拼接的隐式转换
break used within some cycle onlybreak 出现在 if，不在循环内把 break 移进 for 体
EA 日志一直无 [EA2CTP]EA 未挂载 / 未允许交易 / 未到新 K 线确认笑脸图标与 Allow live trading；M1 周期需等下一根 K 线
unknown symbol prefix: xxinstruments 里没有该品种在 config.ini 补上对应合约代码
信号文件长期非空控台未启动或路径不一致核 ea_signal_file 与 EA 实际输出路径是否同一文件
控台进程无故消失PDCurses 会话/窗口被清理改为桌面双击启动，并启用 _watchdog.ps1
只有 GW 行，没有 CTP 行CTP 未登录成功（前置/密码/时段）查 feedserver.log 的 CTP trade login 与 ErrorID
CTP order insert error ErrorID=51 平仓量不足平仓成交后本地持仓缓存的方向算反（SELL CLOSE 被记成空头减少），导致后续平空误判无今仓而用"平昨"标志已修复 ApplyTradeToPosition：平仓方向取委托方向的反向；重启控台会重新查询持仓纠正缓存
orders.csv 出现 0.0000 / 100.0000 的价格控台启动后行情尚未推送，参考价取到 0，保护价变成 20×bidAskDif等 CTP 行情就绪（日志出现行情订阅）再挂 EA；已产生 0 价单需手工撤单/平仓
改了 order_mode=ctp_only 但仍出现 GW 行旧版 exe 的配置白名单只认 parallel/ctp_first，值被丢弃后回落成 parallel重新编译；启动日志确认模式；检查 Debug\config.ini 是否被根配置覆盖
Rebuild 后 ea_signal_file 消失构建会用根目录 config.ini 覆盖 Debug\config.ini把 ea_signal_file 写在根目录 config.ini 里

11 已知限制

限制说明
EA 无法感知成交结果桥接是单向的，EA 用本地 MT4 持仓判断平仓方向，与 CTP 实际持仓并非同一账本
平仓依赖 EA 本地状态CheckForClose() 遍历 MT4 本账户订单，CTP 侧仓位变化不会回写给 EA
每次只写一行FILE_CSV|FILE_WRITE 覆盖写；同一根 K 线内多次触发会覆盖前一条（M1 策略每根 K 线最多一次，正常不冲突）
轮询延迟最坏 800ms，非实时事件驱动
不支持止损单控台只处理 M/L/D 与开平仓，无 S 类型
