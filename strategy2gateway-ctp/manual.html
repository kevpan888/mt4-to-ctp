1 系统概览

SimpleCTPConsole 原为纯行情桥（4444 端口输出 bid/ask 文本）。现改造为“行情双路主备 + 双登录 + 下单路由 + 指令端口”的一体化执行程序。

行情双路主备CTP 行情为主路：10 秒内无 tick 或连接断开即自动切到 aq 网关 SSE；CTP 恢复后自动回切。由 market_source 控制。
双登录CTP 交易链路完整（认证 → 登录 → 结算确认 → 持仓查询，每 30 秒刷新）；aq 网关经内置 gateway/aqgw.py 以 HTTP/JSON 接入。
下单路由parallel 两通道双发；ctp_first 市价单先走 CTP，成交后按累计成交量增量补发网关，超时即放弃网关侧。限价单始终并行。
指令端口TCP 4445，10 列 CSV 文本协议，同步应答 OK/ERR，成交异步推 TRADE。loginNr / groupName 仅落本地流水。

数据流

CTP 行情前置 ─┐
              ├─(主备选择)─► 4444 行情端口 ──► 策略 / 终端
aq 网关 SSE  ─┘

策略 / 终端 ──► 4445 指令端口 ─► OrderRouter
                                   ├─► CTP 交易前置（报单 / 撤单 / 成交回报）
                                   └─► aq 网关 HTTP（open / place / cancel）
                                         └─► 上游 astockquant（自有协议，TLS 直连）

行情回灌 4444 时同时输出三类符号行：CTP 合约名（如 ru2701）、连续主力别名（品种代码小写，如 ru）与具体合约别名（合约小写 + s，如 ru2701s），保证不同下游（策略、终端）都能订阅到自己习惯的名字。

3 启动与编译

3.1 编译

msbuild simple_ctp_console_x86.vcxproj /p:Configuration=Debug /p:Platform=Win32 /m

输出 Debug\SimpleCTPConsole.exe，PostBuild 自动拷贝 CTP 运行库与根目录 config.ini 到 Debug\。

3.2 启动顺序

# 1) 启动内置网关（读取 config.ini，默认端口 8222）
.\start_gateway.ps1            # 加 -Restart 先结束旧网关进程

# 2) 启动控台
.\Debug\SimpleCTPConsole.exe

# 3) 启动策略（可选）
python strategy\ma_cross.py --symbol ru2701 --fast 5 --slow 20 --qty 1
控台进程依赖标准输入存活：后台启动时必须重定向 stdin 并保持句柄打开，否则 Program started. Press Ctrl+C to exit. 后会立即退出。

5 行情端口 4444（保持原有协议）

文本协议，行分隔，\r\n 或 \n 均可。

<服务端> Login:
<客户端> localhost
<服务端> Password:
<客户端> localhost
<服务端> ... granted ...
<客户端> > Symbols:ru2701
# 一次订阅，收到三行（订阅 ru 或 ru2701s 也会拿到同样三行）
<服务端> ru2701   1762060800 19315.0 19320.0 19317.5 ...   # CTP 合约
<服务端> ru       1762060800 19315.0 19320.0 19317.5 ...   # 连续主力别名
<服务端> ru2701s  1762060800 19315.0 19320.0 19317.5 ...   # 具体合约别名

字段：symbol timestamp bid ask ...；策略侧只需 parts[0]、parts[2]、parts[3]。时间戳为秒级。别名规则：连续主力 = 品种代码小写（ru / ag），具体合约 = 合约代码小写 + s（ru2701s）。

6 指令端口 4445

TCP 文本，每行一条指令，10 列 CSV（逗号分隔，末尾 comment 可含逗号，会原样拼回）：

BUYorSELL, lotnr, symbol, price, loginNr, groupName, orderType, OPENorCLOSE, BidAskDif, comment
列取值说明
1BUY / SELL买卖方向（大小写不敏感）
2正整数手数，≤0 返回 ERR invalid lotnr
3合约CTP 合约名（ru2701）；D 指令可空或 * 表示全撤
4价格M 时为参考价，L 时为限价
5loginNr仅写入 orders.csv 与日志，不发任何一侧
6groupName同上，用于审计 / 未来分组
7M / L / S / D市价 / 限价 / 止损（不支持） / 撤单
8OPEN / CLOSE开仓 / 平仓
9BidAskDifM 单价格偏移单位（ru 最小变动价 5）
10commentCTP 写入 BusinessUnit（≤20 字符）；网关截断 31 字符

6.1 指令语义

类型CTP 侧网关侧
M 市价LimitPrice = price ± 20 × BidAskDif（买加卖减）+ IOCaction=open，cmd=buy|sell
L 限价LimitPrice = price + GFDaction=place，cmd=buy_limit|sell_limit
S 止损两侧均不支持，返回 ERR unsupported orderType S
D 撤单撤全部（或仅指定合约）查 /orders 后逐单 cancel
平仓在网关侧就是反向 open：买平 → 网关 sell，卖平 → 网关 buy，不需要 ticket 映射表。网关 symbol 取 CTP 合约字母前缀并转小写（ru2701 → ru）。

6.2 应答格式（原样）

所有应答追加 group=Gxxxxxxxxxx（10 位序号，对应 orders.csv 里的同一指令两侧关联键），便于复盘：

OK ref=000000000002 gw=14123 group=G0000000001   # 并行：两通道 3s 内均返回
OK ref=000000000002 gw=PENDING group=G0000000001 # 并行：网关腿 3s 内未返回，worker 稍后补推 GW_TICKET
OK ref=000000000002 gw=PENDING group=G0000000001 # ctp_first：CTP 已报出，网关待补发
OK cancel ctp=3 gw=1 group=G0000000005            # 撤单：CTP 发出 3 笔，网关完成 1 笔
ERR bad format, need 8+ fields
ERR bad action
ERR bad OPENorCLOSE
ERR invalid lotnr
ERR symbol required
ERR unsupported orderType S
ERR unsupported orderType X
ERR ctp=ctp_not_ready gw=gateway_not_configured
ERR ctp=... gw=...

6.3 异步推送

TRADE 000000000002,19310.0000,1,CTP      # CTP 成交（ref = OrderRef）
TRADE 14123,19240.0000,1.00,GW           # 网关成交（ticket）
GW_TICKET G0000000001,14123               # 并行网关腿异步出结果（gw=PENDING 时必随后推送）
GW_FAIL G0000000001,timeout               # 并行网关腿最终失败

所有推送广播给已连接 4445 的客户端；客户端读循环需按行前缀 TRADE / GW_TICKET / GW_FAIL / OK / ERR 分类处理。

6.4 指令示例

# 市价买开 1 手 ru2701，参考价 19315，ru 最小变动 5
BUY,1,ru2701,19315,,ai_test,M,OPEN,5,ma_golden

# 限价卖开 1 手
SELL,1,ru2701,19330,,ai_test,L,OPEN,5,limit_short

# 市价卖平多头
SELL,1,ru2701,19310,,ai_test,M,CLOSE,5,ma_death

# 全撤（symbol 空或 *）
BUY,1,,0,,ai_test,D,OPEN,5,cancel_all

# 只撤 ru2701
BUY,1,ru2701,0,,ai_test,D,OPEN,5,cancel_ru

7 路由规则

7.1 parallel（默认）

每条指令同时提交 CTP 与网关，互不等待。CTP 同步发出（毫秒级），网关腿放到独立 worker 线程执行，主请求线程最多等 3s：

结果应答说明
两侧成功（3s 内）OK ref=000000000002 gw=14123 group=G0000000001两通道各自建仓，成交由各自推送
网关腿超时OK ref=000000000002 gw=PENDING group=G0000000001CTP 已发；worker 稍后会落盘 GW 行并广播 GW_TICKET G0000000001,14123
网关腿最终失败同上先回 PENDINGworker 广播 GW_FAIL G0000000001,timeout，orders.csv 落 GW ... FAIL 行
仅 CTP 成功OK ref=000000000002 gw=- group=...网关未配置，不走异步分支
两侧失败ERR ctp=... gw=...两侧错误原因原样拼接

3s 有界等待是为了避免网关上游 trade conn 卡顿（常见 4~25s）时拖慢客户端应答。网关腿真实超时上限由 GwClient 控制（30s），worker 会一直等到结果再推送。客户端收到 gw=PENDING 后应继续在 socket 上读，直到收到同 groupKey 的 GW_TICKET 或 GW_FAIL。

parallel 模式下 CTP 与网关是两笔独立仓位，不是同一笔单的备份；请按用途选择模式。

7.2 ctp_first（市价单先 CTP）

仅对 M 市价单生效，L 限价单在两种模式下都走 parallel：

  1. 先向 CTP 报单；CTP 未就绪或报单失败直接返回 ERR ctp=...，不再发网关。
  2. CTP 报出成功先回 OK ref=000000000002 gw=PENDING。
  3. 收到 CTP 成交（OnRtnTrade）后，按“累计成交量 − 已补发量”的增量向网关发 open，保证部分成交只补实际成交量。
  4. 超过 ctp_first_timeout_ms（默认 3000ms）仍未成交，或委托被全拒/撤销，则放弃网关侧并记日志。

实测链路：

OK ref=000000000002 gw=PENDING
TRADE 000000000002,19310.0000,1,CTP
Gateway order ok: ru BUY lots=1 ticket=14097
TRADE 14097,19305.0000,1.00,GW

7.3 撤单（D）

两侧并行执行，任一侧成功即为 OK：

  • CTP：CancelAll，symbol 为空或 * 表示全撤，否则只撤该合约。刚报出但尚未收到交易所确认的委托会等待 ≤500ms 补上 OrderSysID；仍拿不到则跳过并记 CTP cancel deferred ref=...，避免 ErrorID=148。
  • 网关：查 /orders 找出活动委托，逐笔 cancel；上游撤单通常只回进度帧，客户端在超时后复查挂单表确认已消失即判成功。
OK cancel ctp=3 gw=1
ERR ctp=- gw=gateway_not_configured

7.4 通道不可用时的行为

情况行为
CTP 未 ready（未登录/断线）CTP 侧记 ctp_not_ready；parallel 仍走网关，ctp_first 直接返回 ERR
网关未配置或不可达网关侧记 gateway_not_configured / bad_response；parallel 仍走 CTP
S 止损两侧都不发，返回 ERR unsupported orderType S
两侧都不可用返回 ERR ctp=... gw=... 或 ERR no trading channel

11 故障排查

现象原因与处理
ErrorID=141 密码已过期登录被拒；在 SimNow 网站重置密码后更新 userPassword（根与 Debug\config.ini），重启控台
ErrorID=148 ExchangeID 无效撤单时 OrderSysID 为空却填了 ExchangeID；代码已改为仅在 OrderSysID 非空时填，未确认委托会 deferred
ErrorID=26 已全成交或已撤销等待 OrderSysID 期间委托已终止才发撤单，属无害日志
ErrorID=48 价格不是最小变动价位的整数倍客户端传入的 price 未对齐合约 tick（行情中间价常带 0.5 尾数）。市价单会在此基础上再叠加 ±20×BidAskDif，因此报价前必须先把 price 对齐到 tick；策略侧已按 --tick 四舍五入
ErrorID=51 平仓手数不足该侧没有对应方向的持仓（常见于两通道实际成交不同步）；不是协议错误，核对 /positions 与 CTP 持仓即可
网关持仓数量持续增加网关的“平仓”是按反向开仓实现，会生成新 ticket 而不是冲销旧 ticket；净敞口正确但每张票据仍占用保证金。长跑策略需定期按 GET /positions 逐票 close 清理
4445 应答慢（数秒到 30 秒）并行/先 CTP 模式下网关腿是同步请求，上游卡顿会拖慢应答；客户端读超时应设为 ≥35 秒，live_test.py 与 ma_cross.py 已按此设置
委托 status=5 SHFE:当前状态禁止报单非交易时段（11:30–13:30、15:00 后）；交易时段恢复即可
ctp_not_ready认证/登录/结算确认未完成或断线；看日志 CTP trade ready 与 FrontID/SessionID
网关 bad_response / 请求超时上游 trade conn 被断开；网关已内置自动重连（发单前探测连接、断开则重建，最多 3 次）。若仍持续失败，看 /health 的 trade_reconnects / last_error；需要时可 POST /reconnect 强制重建
下单返回 order state unknown请求已发出后连接断线，网关不会自动重发（避免重复委托）；先查 GET /orders 与 GET /positions 核对，再决定是否补单
网关进程随终端退出消失Start-Process 启动的进程可能随父 shell 结束被回收；常驻请在后台 shell 直接运行 python aqgw.py ...
